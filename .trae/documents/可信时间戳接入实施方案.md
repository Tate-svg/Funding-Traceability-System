# 可信时间戳接入实施方案

## Context

现有系统已有两层存证基础：只读操作日志（`operation_log` 表 + `@OperationLog` AOP，26 个业务节点全部已标注，覆盖资料上传/申请提交/审核/拨付/回访/凭证修改）与凭证 SHA-256 哈希（`HashUtils`）。本次在其上接入**系统原生可信时间戳**能力：

- 时间戳由后端切面自动生成（本地模拟 TSA，预留接口后续替换真实时间戳服务），前端不可传入
- 每条台账记录一对一绑定时间戳，全局序列号 + SHA-256 哈希链固化业务时序，可核验、不可篡改
- 写入时检测时序倒序自动标记预警；提供链核验接口
- 资金台账导出附带时间戳与存证标识
- 前端：溯源台账卡片页（时间戳徽章+节点色卡）、资金详情页升级为可信存证时间轴（水印底纹、异常红框高亮）

已确认决策：**时间戳/台账数据仅 AUDIT_ADMIN 与 SUPERVISOR 可见**（复用现有 `log:view` 权限点，SPONSOR 不受影响）。

---

## 一、数据库（backend/src/main/resources/sql/schema.sql）

新增 `timestamp_record` 表（DROP 列表同步追加）：

```sql
CREATE TABLE timestamp_record (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    serial_no BIGINT NOT NULL UNIQUE,      -- 全局时序号，递增，固化全链路顺序
    biz_type VARCHAR(50) NOT NULL,          -- fund/student/visit/score/score_item/sys_user/review_task
    biz_id BIGINT,                          -- 业务单据 ID
    node VARCHAR(30) NOT NULL,              -- 节点编码：SUBMIT/AUDIT_PASS/AUDIT_REJECT/REVIEW/REVIEW_DRAW/DISBURSE/VOUCHER_MODIFY/VISIT_RECORD/STUDENT_UPLOAD/OTHER
    node_name VARCHAR(50),                  -- 节点显示名，如"提交申请"
    summary VARCHAR(200),                   -- 业务摘要，如"新增资助申请 | Fund(id=8 ...)"
    operator_id BIGINT, operator_name VARCHAR(50), role VARCHAR(20),
    ts_time DATETIME,                       -- 时间戳时刻（本地模拟 TSA 盖章时间）
    ts_hash VARCHAR(64) NOT NULL,           -- SHA-256(prev_hash|serial|biz|node|ts_time|operator|summary)
    prev_hash VARCHAR(64),                  -- 链上前一条哈希
    anomaly TINYINT DEFAULT 0,             -- 1=时序倒序预警
    anomaly_reason VARCHAR(200),
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_ts_biz (biz_type, biz_id),
    INDEX idx_ts_serial (serial_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

防篡改机制：任何一条记录内容被改，其后所有 `ts_hash` 重算都对不上（链式依赖 `prev_hash`），核验接口可定位断裂点。

## 二、后端

### 2.1 新增文件
| 文件 | 说明 |
|---|---|
| `entity/TimestampRecord.java` | 表实体（@TableName，LocalDateTime 字段走全局 Jackson 格式化） |
| `mapper/TimestampRecordMapper.java` | **只读风格**（同 OperationLogMapper 约定，不继承 BaseMapper）：`insert`、`selectPage`（biz_type/biz_id/node/keyword 过滤，serial_no DESC）、`selectLast`（按 biz 取最新一条）、`selectAllOrdered`（核验用，serial ASC） |
| `service/TimestampService.java` | 接口：`stamp(...)`、`page(...)`、`verify(bizType, bizId)`；**预留真实 TSA 替换点**（类注释说明：替换 LocalTimestampServiceImpl 为调用真实时间戳接口的实现即可） |
| `service/impl/LocalTimestampServiceImpl.java` | 本地模拟实现（`synchronized` 生成 serial_no=MAX+1；ts_time=LocalDateTime.now()；哈希链计算；时序检测；落库） |
| `controller/TimestampController.java` | `GET /api/timestamps`（分页，`@RequirePermission("log:view")`）、`GET /api/timestamps/verify`（同权限，返回 `{valid, chainBroken, nodes:[{serialNo,node,nodeName,tsTime,anomaly,reason}...]}`） |
| `common/SeedTimestampRunner.java` | ApplicationRunner：`timestamp_record` 空表时为存量种子数据补盖时间戳（fund 1~7 的提交/审核/拨付节点、student/visit 的资料与回访节点），按业务时间（create_time/audit_time/disburse_time）排序依次调用 `stamp`，保证哈希链正确；重跑 schema 后自动重建演示链 |

### 2.3 切面接入（common/OperationLogAspect.java）

`around()` 在写完 operation_log 后追加：`timestampService.stamp(ann.value(), ann.type(), pjp.getArgs())`，同样 try-catch 仅 warn 不影响业务。stamp 内部完成：解析节点 → serial+ts_time 生成 → **时序倒序检测**（同 biz_type+biz_id 的上一条 `ts_time` 与本条比较，倒序则 `anomaly=1` 并记录 reason，仅标记不阻断）→ 哈希链计算 → insert。

### 2.4 导出（FundServiceImpl.export，L118-137 动态 headers/rows）

headers 追加 4 列：`业务节点数 | 时间戳序列 | 最新存证哈希 | 存证标识`；每行从 `timestamp_record` 查该 fund 的记录集：节点数、`#首-#末` 序列区间、最新 ts_hash 前 16 位缩略、全部有链则显示「✓ 可信存证」否则「—」。其他导出（学生/回访/评分）本次不动。

## 四、关键风险
1. serial 生成与哈希链计算用 `synchronized` + 单条 insert，Demo 并发可接受；UNIQUE(serial_no) 兜底
2. 核验是**全链重算**（selectAllOrdered 顺序重算比对 ts_hash），数据量大时演示场景可接受
3. SeedTimestampRunner 仅空表执行（COUNT=0 判断），幂等；用业务时间盖章避免与真实操作时间错乱
4. 切面 stamp 失败仅 warn，不阻断业务（与现有日志策略一致）
5. 脱敏不变：时间戳记录不含敏感字段原文，summary 复用日志 content 内容（DISBURSE_ADMIN 不涉及）

## 五、实现顺序
1. schema.sql 加表 → 实体/Mapper → TimestampService/LocalTimestampServiceImpl → 切面接入（后端编译通过）
2. TimestampController + SeedTimestampRunner → Fund export 加列
3. 前端 api/trace.js → TraceLedger.vue → TraceTimeline.vue → FundDetail 替换 → 路由
4. 联调验证

## 六、端到端验证
- 空库重跑 schema.sql → 启动后端 → `timestamp_record` 自动生成种子链（fund 1~7 各节点）→ `GET /api/timestamps` 返回有序数据
- audit_admin：新建申请/审核 → 台账出现新节点且 serial 递增；`GET /api/timestamps/verify?bizType=fund&bizId={id}` 返回 valid=true
- supervisor：登录看溯源台账卡片与色卡；资金详情页时间轴水印/锁标识正常
- 时序异常演示：手动 `UPDATE timestamp_record SET ts_time=...` 篡改一条 → verify 返回 chainBroken/异常节点 → 前端红色边框+hover 预警
- 导出资金流水：新增 4 列含时间戳序列与「✓ 可信存证」标识
- 越权：DISBURSE_ADMIN/SPONSOR 调 GET /api/timestamps 应 403
