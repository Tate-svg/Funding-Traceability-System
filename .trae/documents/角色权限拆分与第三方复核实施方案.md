# 角色权限拆分与第三方复核实施方案

## Context

现有系统为单一 ADMIN 角色（`@AdminOnly` 注解硬编码 "ADMIN" 校验），资金单（fund 表）无状态字段，创建即生效。本次改造实现职责分离与第三方监督：

- ADMIN 完全移除，拆为 **AUDIT_ADMIN（审核管理员）**、**DISBURSE_ADMIN（拨付管理员）** 互斥角色，新增 **SUPERVISOR（监事/审计）**，SPONSOR 保持不变
- 资金单引入状态机：`SUBMITTED → AUDITED(驳回 REJECTED) → REVIEWED → DISBURSED`
- 大额单（≥5000 元，审核通过后）自动进入复核池，监事按比例随机抽检
- 操作日志只读存证（凭证号 + SHA-256 哈希），不可篡改
- 前端分角色工作台 + 时间轴日志 + 进度条详情页

用户已确认：阈值 5000 元；ADMIN 移除、系统配置归 AUDIT_ADMIN；按比例随机抽取；凭证号+哈希存证。

## 二、后端改造

### 2.1 权限体系重构（替换硬编码 ADMIN）
- 新增 `common/RequirePermission.java`：`String[] value()` 权限点，满足任一放行（标注方法/类，替代并删除 AdminOnly.java）
- 新增 `common/PermissionHolder.java`：启动时全量加载 role_permission 至 `Map<role, Set<permission>>`，提供 `hasPermission(role, points)`（Demo 不做运行期刷新）
- 改造 `common/RoleInterceptor.java`：读 `RequirePermission` 注解（方法优先类兜底），调 PermissionHolder 校验；失败保持现有 `{"code":403,"message":"权限不足"}` 响应（前端拦截器无需改动）
- WebMvcConfig 注册顺序不变（Jwt → Role）

### 2.2 字段级权限隔离（Service 层 VO 裁剪）
- `FundServiceImpl` 增加私有 `maskByRole(FundVO)`：DISBURSE_ADMIN 查询时 `purpose/remark` 置 null（申请资料锁定）；SPONSOR 维持 sponsor_id 过滤现状；AUDIT_ADMIN/SUPERVISOR 全量
- FundVO 增加 status/voucherNo/voucherHash/auditTime/disburseTime 等字段
- 安全底线：脱敏在服务端，越权写操作由 `@RequirePermission` 403 拦截，双层防护；export 仅 AUDIT_ADMIN 天然规避

### 2.3 资金状态机与新接口
- 并发防护：所有状态迁移用**条件 UPDATE**（`UpdateWrapper.eq("id",id).eq("status",前置状态)`），影响行数=0 抛 `BusinessException(400,"单据状态已变化，请刷新")`，杜绝重复审核/拨付
- audit() 加 `@Transactional`，同事务生成凭证号+哈希并落库

| 方法 | URL | 权限点 | 说明 |
|---|---|---|---|
| GET | /api/funds?status= | fund:view | 分页按角色脱敏 |
| GET | /api/funds/pending-audit | fund:audit | 待审核列表（SUBMITTED） |
| GET | /api/funds/pending-disburse | fund:disburse | 待拨付（AUDITED 且 <5000，或 REVIEWED） |
| POST | /api/funds/{id}/audit | fund:audit | 体 `{result:"PASS"/"REJECT", remark}`；PASS 生成凭证、≥5000 入复核候选 |
| POST | /api/funds/{id}/disburse | fund:disburse | 前置 AUDITED(小额)/REVIEWED，条件 UPDATE |
| POST | /api/funds | fund:create | 强制 status=SUBMITTED |
| PUT/DELETE | /api/funds/{id} | fund:update/delete | 仅 SUBMITTED/REJECTED 可编辑，仅 SUBMITTED 可删 |
| POST | /api/review-tasks/draw | review:draw | 体 `{minAmount,maxAmount,ratio}` → `{batchNo,total,drawn}` |
| GET | /api/review-tasks | review:finish | 任务分页（batch_no/status 过滤） |
| POST | /api/review-tasks/{id}/finish | review:finish | 体 `{result,remark}`；PASS→REVIEWED，FAIL→打回 SUBMITTED |
| GET | /api/operation-logs | log:view | 日志分页，**唯一接口**（无写接口） |

### 2.4 凭证号 + SHA-256 存证
- 位置：FundServiceImpl.audit()；凭证号 = `Voucher-yyyyMMdd-` + 4 位序号（当日 count+1，方法 `synchronized`，voucher_no UNIQUE 索引兜底，DuplicateKeyException 由全局异常处理转 400 重试提示）
- 新增 `util/HashUtils.java`：SHA-256(`voucherNo|fundId|studentId|amount|auditTime`) hex 输出

### 2.5 操作日志（AOP，结构性只读）
- 新增 `common/OperationLog.java` 注解（`value` 描述 + `type` 编码）+ `common/OperationLogAspect.java`：`@Around` 先执行业务成功后插日志，`UserContext` 取操作人/角色，日志失败仅 warn 不影响业务（同步插入，不用 @Async 避免 ThreadLocal 丢失）
- `OperationLogMapper` **不继承 BaseMapper**，只声明 `insert` 与 `selectPage`（注解 SQL 风格同 FundMapper），从结构上杜绝 update/delete
- 审核/驳回/拨付/抽检/复核/导出/用户增删改等约 15 处标注

### 2.6 随机抽检（ReviewTaskServiceImpl.draw，@Transactional）
1. 候选池：`status='AUDITED' AND amount>=5000 AND id NOT IN (SELECT fund_id FROM review_task)` + 金额区间过滤
2. `n = max(1, ceil(候选数 × ratio/100))`，`ORDER BY RAND() LIMIT n` 抽取
3. 批次号 `B+yyyyMMddHHmmss`，批量插入 review_task(PENDING)
4. **轮空放行**：同批候选未抽中者条件 UPDATE 为 REVIEWED（视为经抽检程序筛过）
5. 阈值 5000 放 application.yml `funding.review.threshold`，@Value 注入
- finish()：条件 UPDATE 任务状态；PASS→fund REVIEWED / FAIL→fund 打回 SUBMITTED；两步一个事务

### 2.7 现有 Controller 权限点迁移
- `@AdminOnly` 全部替换：Fund 写操作→`fund:create/update/delete`、export→`fund:export`；Student/Visit/Score 写操作及导出→各自 `*:manage`；ScoreItem 写→`scoreItem:manage`；SysUser 写→`user:manage`（/options 保持无注解）
- GET 查询类接口维持无注解（登录即可），SPONSOR 数据过滤逻辑全部保留

## 四、关键风险

1. 旧 token role=ADMIN 失效 → 提示重新登录即可
2. 状态迁移必须条件 UPDATE，禁止先查后改（双击/并发防重）
3. 抽检候选必须排除已在 review_task 中的单（防重复抽检）；draw 事务保证插任务+轮空放行原子性
4. OperationLogMapper 不继承 BaseMapper 为硬性约定
5. 脱敏只改 Service 出口（page/getById/pending-disburse），勿遗漏
6. 改造后用 sponsor 账号回归数据可见性

## 五、实现顺序

1. **地基**：schema.sql 重写 → entity/mapper（OperationLogMapper 只 insert/select）→ RequirePermission/PermissionHolder/RoleInterceptor → 全 Controller 注解迁移。**验证**：四账号登录、越权 403
2. **状态机主干**：Fund 状态约束 → audit（凭证+哈希）→ 日志 AOP → 审核工作台 + FundDetail 进度条。**验证**：提交→审核→驳回分支、日志带锁
3. **复核与拨付**：draw/finish → disburse → 拨付/复核池页面 → VO 脱敏。**验证**：6000 元走 AUDITED→抽检→REVIEWED→DISBURSED；3000 元直接拨付；拨付员看不到用途
4. **收尾**：日志时间轴页 → Layout/User 角色文本 → 登录跳转 → Fund.vue 状态列
5. **联调**：四角色走查 + sponsor 回归 + 空库重跑 schema.sql
