# 双库隔离 + 双层脱敏 + 权限分级 隐私保护实施方案

## 一、背景与目标

当前系统所有数据（含学生姓名/身份证/电话/住址等明文隐私）同库存储，仅对 DISBURSE_ADMIN 做了用途/备注置空，隐私保护薄弱。本次落地三层防护：

1. **双库隔离**：业务流水库 `funding_db` 只存虚拟ID、金额、流转节点等业务数据；学生隐私独立存 `funding_privacy` 库并 AES 加密，通过 virtual_id 一对一映射
2. **双层脱敏**：前端表单实时检测提示本地脱敏（第一层）+ 服务端脱敏引擎二次校验、未脱敏拦截留痕（第二层）
3. **权限分级**：普通岗位默认只见脱敏数据；明文调取需「审核管理员初审 → 监事终审」两级审批，限时可见，全程留痕

## 二、已确认决策

| 决策点 | 结论 |
|---|---|
| 双库方式 | 同 MySQL 实例两个库，后端双 DataSource，禁止跨库 JOIN |
| 隔离范围 | 仅学生隐私（name/id_card/phone/family_address/family_situation） |
| 审批层级 | 两级：AUDIT_ADMIN 初审 → SUPERVISOR 终审 |
| 上传演示 | 学生表单新增「证明材料」上传（.txt），上传后进入脱敏预览态 |

## 三、库表设计（schema.sql 改造）

> 注意：schema.sql 为全量重建脚本（含 DROP DATABASE），执行即清空现有数据。

### funding_privacy 库（新建）
```sql
CREATE DATABASE funding_privacy DEFAULT CHARSET utf8mb4;
CREATE TABLE privacy_profile (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  virtual_id VARCHAR(20) NOT NULL UNIQUE,        -- 映射业务库 student.virtual_id
  name_enc VARCHAR(255), id_card_enc VARCHAR(255), phone_enc VARCHAR(255),
  family_address_enc VARCHAR(512), family_situation_enc TEXT,   -- 均为 AES Base64 密文
  create_time DATETIME, update_time DATETIME
);
```

### funding_db 改造/新增
- **student 重建**：去除隐私列，改为 `(id, virtual_id UNIQUE, mask_name, gender, school, grade, sponsor_id, create_time, update_time)`；fund/visit 的 student_id 关联不变
- **privacy_access_apply**（调取审批单）：applicant_id/applicant_name、virtual_id、field_scope、reason、status(PENDING_L1→PENDING_L2→APPROVED/REJECTED)、l1_by/l1_time/l1_remark、l2_by/l2_time/l2_remark、expire_time（终审通过 +2h）
- **privacy_access_log**（明文调取留痕，只读表不继承 BaseMapper）：apply_id、user_id、username、virtual_id、fields、create_time
- **mask_violation_log**（脱敏拦截记录，只读）：user_id、username、api、field、rule、hit_text、create_time
- **student_attachment**（上传材料）：student_id、file_name、file_path、mask_status(PENDING/CONFIRMED)、masked_text、create_time
- **种子改造**：student INSERT 只写 virtual_id/mask_name/非敏感列；明文五字段以密文写入 privacy_profile 种子（离线用演示密钥预加密）；role_permission 追加 `privacy:apply`（全角色）、`privacy:approve:l1`（AUDIT_ADMIN）、`privacy:approve:l2`（SUPERVISOR）

## 四、后端设计

### 1. 双数据源（最大风险点：自动装配冲突）
- application.yml：`spring.datasource` 拆为 `spring.datasource.business`（funding_db，@Primary）与 `spring.datasource.privacy`（funding_privacy）；新增 `funding.privacy.aes-key`（16 位）
- 新建 `config/BusinessDataSourceConfig`、`config/PrivacyDataSourceConfig`：各自声明 DataSource + SqlSessionFactory + SqlSessionTemplate，分别 `@MapperScan("com.funding.mapper")` / `@MapperScan("com.funding.privacymapper")`
- 移除 FundingApplication 上的 @MapperScan；手动建 SqlSessionFactory 后 yml 的 mybatis-plus 全局配置不再自动生效，需在两个工厂内显式设置 map-underscore-to-camel-case、log-impl、分页插件（复用 MyBatisPlusConfig 的 MybatisPlusInterceptor Bean）
- 跨库关联在 Service 层手工拼装：先查业务库得 virtual_id，再查隐私库，**不做跨库 JOIN**

### 2. 加密与脱敏引擎（util 包，与 HashUtils 并列）
- `CryptoUtils`：AES/ECB/PKCS5Padding，encrypt/decrypt 返回 Base64，密钥读 yml
- `MaskingEngine`：规则表 ID_CARD `\d{17}[\dXx]`、PHONE `1[3-9]\d{9}`、BANK_CARD `\d{16,19}`、LONG_DIGIT `\d{8,}`；API：`scan(text)→List<Hit{start,end,rule,text,masked}>`、`autoMask(text)`；打码规则：手机 `138****5678`、身份证前3后4、卡号前4后4

### 3. 二次脱敏校验（第二层）
- 挂载点：FundServiceImpl.saveFund/updateFund/audit(remark)、VisitServiceImpl 新增/修改、Student 表单文本（family_situation 等）
- 写入前 `MaskingEngine.scan()`，命中未打码敏感内容 → 写 mask_violation_log + 抛 BusinessException(400, "含未打码敏感信息:字段/规则")，前端红框提示

### 4. 学生链路改造
- saveStudent：生成 `virtual_id = "STU-" + 12位hex`；五隐私字段加密写 privacy_profile；业务库写 mask_name（首字+"**"）+ 非敏感字段；两库先后写，异常提示重试
- StudentMapper SQL 改新列名；StudentVO 输出 virtualId/maskName/masked 标记；列表、详情、导出默认只出业务库脱敏数据（导出列同步去掉明文列）；SPONSOR 数据隔离逻辑不变

### 5. 隐私调取审批流（PrivacyAccessController）
| 接口 | 权限点 | 说明 |
|---|---|---|
| POST /api/privacy/access/apply | privacy:apply | 填 virtualId/字段范围/理由 |
| POST /api/privacy/access/{id}/approve | privacy:approve:l1 / l2 | result+remark；终审通过置 APPROVED 且 expire_time=now+2h；任一级驳回即 REJECTED |
| GET /api/privacy/access/mine | 登录 | 我的申请及状态 |
| GET /api/privacy/access/todo | l1/l2 | 待我审批列表 |
| GET /api/privacy/profile/{virtualId} | 登录 | 有有效 APPROVED 申请 → 解密返明文 + 写 privacy_access_log；否则返脱敏数据 |
- 审批/申请操作复用 @OperationLog + 时间戳切面自动留痕盖章

### 6. 材料上传 + 脱敏预览
- POST /api/students/{id}/attachments：MultipartFile 仅 .txt，存 `upload/attachments/{studentId}/`，读文本 scan → 返回 {attachmentId, originalText, hits[]}
- POST /api/students/{id}/attachments/{attId}/confirm：提交前端确认后的打码文本，写 masked_text、置 CONFIRMED；未确认前 PENDING

## 五、前端设计

### 可复用新组件
- `components/PrivacyTipBar.vue`：浅蓝常驻提示条「请优先本地脱敏后再上传…」
- `components/ComplianceFooter.vue`：页面底部隐私合规小字
- `components/SensitiveTextarea.vue`：封装 textarea，输入时跑与后端同款正则；命中 → 红色边框 + 右侧浮动提示（命中规则）+「一键打码」按钮；存在未处理命中时 emit block，禁用提交按钮

### 页面改造
- **Student.vue**：列表姓名/身份证/电话列默认打码；「调取明文」按钮 → 理由+字段范围弹窗 → 我的申请状态跟踪；审批通过且未过期时详情区展示明文 + 倒计时；新增「证明材料上传」区 → 上传后弹 `AttachmentMaskPreview.vue`（命中片段自动打码高亮、可划选手动补打码、未处理命中红框+浮动提示、未脱敏禁止确认）；表单页顶挂 PrivacyTipBar、底部挂 ComplianceFooter
- **Fund.vue / Visit.vue**：purpose/remark/content 等换 SensitiveTextarea + 顶/底组件
- **PrivacyApprove.vue**（新页面）：Tab「我的申请 / 初审待办(AUDIT_ADMIN) / 终审待办(SUPERVISOR)」，审批弹窗填意见；路由 `/privacy/approve`，菜单按 roles 显示
- api 新增：`api/privacy.js`、`api/attachment.js`

## 六、实施顺序

1. schema.sql：funding_privacy 库 + 新表 + student 重建 + 种子改造（执行前提醒清库）
2. 双数据源配置 + CryptoUtils + MaskingEngine（编译通过后单测打码规则）
3. 学生链路改造（Mapper/VO/导出）+ 二次脱敏校验挂载
4. 审批流接口 + 明文查看留痕
5. 上传 + 确认接口
6. 前端组件与页面
7. 联调验证（对照第七节）

## 七、端到端验证清单

| 验证项 | 预期 |
|---|---|
| 双库隔离 | `SELECT * FROM funding_db.student` 无任何明文隐私列；privacy_profile 五字段均为 Base64 密文 |
| 新增学生 | 业务库落 mask_name+虚拟ID，隐私库落加密五字段，virtual_id 一致 |
| 二次脱敏拦截 | remark 填"电话13800000011"提交 → 400 + mask_violation_log 有记录 + 前端红框浮动提示 |
| 前端第一层 | 文本域输入手机号 → 红框+浮动提示+一键打码；未处理禁用提交 |
| 两级审批 | SPONSOR 申请 → 审核管理员通过 → 监事通过 → 2h 内可看明文；任一级驳回即终止；过期后回落脱敏 |
| 明文留痕 | 每次明文调取 privacy_access_log 新增（谁/何时/哪生/哪些字段/申请单号），只读不可改 |
| 越权 | 无 privacy:approve 权限角色审批 → 403；无有效申请调取明文 → 仅得脱敏数据 |
| 上传预览 | 上传含手机号 txt → 预览态自动打码+可调整；未处理命中禁止确认 |
| 默认打码展示 | 学生列表/详情/导出均为脱敏态 |
