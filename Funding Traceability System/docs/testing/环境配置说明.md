## 三、后端（profile = test）

### 3.1 关键配置（`backend/src/main/resources/application-test.yml`）

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| `server.port` | 8090 | 与演示服务 8080 隔离 |
| `spring.datasource.business.jdbc-url` | `jdbc:mysql://localhost:3306/funding_test...` | 业务测试库 |
| `spring.datasource.privacy.jdbc-url` | `jdbc:mysql://localhost:3306/funding_privacy_test...` | 隐私明文测试库 |
| `spring.datasource.business.maximum-pool-size` | 60 | 压测连接池 |
| `spring.datasource.privacy.maximum-pool-size` | 30 | 隐私库连接池 |
| `server.tomcat.threads.max` | 300 | 压测工作线程 |
| `server.tomcat.accept-count` | 200 | 排队上限 |
| `funding.mybatis.stdout-sql-log` | false | 关闭 SQL 控制台打印，避免压测 I/O 成为瓶颈 |
| `logging.file.name` | `logs/backend-test.log` | 后端运行日志（相对 `backend` 目录） |

> 两个数据源配置类通过 `@Value("${funding.mybatis.stdout-sql-log:true}")` 控制 `StdOutImpl`，默认（未配置 profile）行为不变。

### 3.2 构建

```powershell
cd backend
& "D:\apache-maven-3.9.6\bin\mvn.cmd" -B clean package -DskipTests
```

### 3.3 启动 / 停止

```powershell
cd backend
Start-Process "D:\java\bin\java.exe" `
  -ArgumentList "-jar","target\funding-traceability-1.0.0.jar","--spring.profiles.active=test" `
  -WorkingDirectory (Get-Location)
```

> 若在自动化终端中启动，子进程可能随终端结束被回收；建议用 `docs/testing/scripts/start-test-backend.ps1` 或独立命令行窗口启动。

停止（按 8090 端口定位进程）：

```powershell
$pid8090 = (Get-NetTCPConnection -LocalPort 8090 -State Listen | Select-Object -First 1).OwningProcess
Stop-Process -Id $pid8090 -Force
```

### 3.4 健康检查

```powershell
Invoke-WebRequest -Uri "http://localhost:8090/api/auth/login" -Method POST `
  -ContentType "application/json" `
  -Body '{"username":"sponsor","password":"123456"}'
```

返回 `HTTP 200` 且 `data.token` 非空即启动成功，启动耗时约 4～5 秒。

```powershell
cd "d:\Funding Traceability System\Funding Traceability System"
```

### 5.2 执行（需后端 8090 已启动）

```powershell
node .tools/newman/node_modules/newman/bin/newman.js run `
  docs/testing/postman/Funding-Traceability.postman_collection.json `
  -e docs/testing/postman/Funding-Traceability.postman_environment.json `
  -r cli,json,htmlextra `
  --reporter-json-export docs/testing/evidence/postman-result.json `
  --reporter-htmlextra-export docs/testing/evidence/postman-report.html
```

- `00-前置` 目录会登录 6 个角色并把 Token 写入环境变量，后续目录自动复用。

- 环境文件中的 `baseUrl` 默认 `http://localhost:8090`；切换主机只需改环境变量或 `--env-var baseUrl=http://...`。
- 执行前建议重置测试库（第 2.1 节），避免历史申请单影响断言。

## 六、JMeter 性能测试

### 6.1 安装（一次性）

1. 下载 `apache-jmeter-5.6.3.tgz`（约 83 MB）：
   - 官方：`https://archive.apache.org/dist/jmeter/binaries/apache-jmeter-5.6.3.tgz`
   - 国内镜像：`https://mirrors.aliyun.com/apache/jmeter/binaries/apache-jmeter-5.6.3.tgz`
2. 解压到仓库根 `.tools`：

```powershell
New-Item -ItemType Directory -Force -Path .tools | Out-Null
tar -xzf "$env:TEMP\apache-jmeter-5.6.3.tgz" -C .tools
Test-Path ".tools\apache-jmeter-5.6.3\bin\jmeter.bat"   # 应为 True
```

3. `jmeter.bat` 通过 **PATH 中的 `java`** 启动，必须先把 JDK 加入 PATH：

```powershell
$env:PATH = "D:\java\bin;" + $env:PATH
```

### 6.2 执行

```powershell
cd docs/testing/jmeter
..\..\..\.tools\apache-jmeter-5.6.3\bin\jmeter.bat -n `
  -t Funding-Traceability-Performance.jmx `
  -JTHREADS=500 -JLOOPS=5 -JRAMP_UP=2 `
  -l ../evidence/jmeter-result.jtl `
  -j ../evidence/jmeter.log `
  -e -o ../evidence/jmeter-report
```

- `-n` 非 GUI；`-e` 生成 Dashboard；`-o` 指定报告目录（**目录必须不存在或为空**）。
- 变量均支持 `-J` 覆盖：`THREADS / LOOPS / RAMP_UP / PORT / BASE_URL / USERNAME / PASSWORD / VIRTUAL_ID / FUND_ID`。
- `setUp` 线程组自动登录 `sponsor` 并提取 `data.token` + 核验码，通过 `props.put` 全局共享，主线程组用 `${__P(perfToken)}` 复用，无需手工填写。
- 控制台会输出 `summary` 与 `Active / Started / Finished` 线程数；完整数据看 JTL 与 Dashboard。

### 6.3 关键报告字段

`docs/testing/evidence/jmeter-report/index.html`：

- **Statistics**：样本数、错误率（`Error %`）、平均 / 中位数 / P90 / P95 / P99 / 最大响应时间、TPS（`Transactions/s`）。
- **Errors / Top 5 Errors**：错误明细。
- 本次实测：5002 请求、错误率 0.00%、总 TPS 452.9、峰值在线 494。

## 八、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `8090` 端口占用 | 旧 test 后端未退出 | 按 3.3 节按端口杀进程后重启 |
| `jmeter.bat` 提示 `Not able to find Java executable or version` | PATH 中没有 java | `$env:PATH = "D:\java\bin;" + $env:PATH` |
| JMeter 报 `Results file ... is not empty` | JTL 已存在 | 删除 `.jtl` 后重跑 |
| JMeter 报 `Output folder ... is not empty` | 报告目录已存在 | 删除 `jmeter-report` 目录后重跑 |
| newman 命令找不到 | 未安装或未用本地路径 | 用 `node .tools/newman/node_modules/newman/bin/newman.js ...` |
| newman 断言失败 | 测试库有历史申请单 / 会话 | 执行 `init_test_db.sql` 重置后重跑 |
| 后端启动报 `Access denied` | MySQL 密码不一致 | 修改 `DB_PASSWORD` 环境变量或 `application-test.yml` 默认值 |
| PowerShell 禁止运行脚本 | 执行策略 | `powershell -ExecutionPolicy Bypass -File docs/testing/run-all.ps1` |

## 九、隔离与安全要求（必须遵守）

1. **仅测试库**：profile `test` 已硬编码 `funding_test` / `funding_privacy_test`；压测与接口测试全程不连接演示库。
2. **压测前重置、压测后清理**：保证结果可重复，且不会留下 2500 条压测数据。
3. **不提交工具与日志**：`.tools/` 与 `*.log` 已加入 `.gitignore`，仅 `docs/testing/evidence/*.log` 作为交付证据保留。
4. **账号仅测试库有效**：`sponsor2`、`audit_admin2`、`supervisor2` 等为测试库种子账号，演示库无此账号。
5. 生产环境需替换：明文密码 → BCrypt、JWT 吊销/刷新、异常信息统一脱敏（见测试报告风险 R-01/R-03/R-04/R-05）。
